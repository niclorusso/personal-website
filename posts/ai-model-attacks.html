AI model attacks in practice: membership inference and prompt injection

I built this project as a full stack security portfolio artifact, from data and model setup through attack implementation, evaluation, and result analysis. The code is a reproducible PyTorch and HuggingFace project with runnable scripts, metrics exports, and plots. The repository is on GitHub: github.com/niclorusso/ai-model-attacks.

Scope and goals

Membership inference (privacy): infer whether a sample was part of model training. Prompt injection (security): test adversarial prompts that attempt to override policy. Reproducibility: CLI configurable experiments with stored setup metadata and generated artifacts.

Experiment 1: Membership inference

The full run uses target and shadow modeling on HuggingFace datasets and transformers. Dataset ag_news. Target model distilbert-base-uncased fine tuned for classification. Two independently trained shadow classifiers. Attack features per sample: loss, predicted confidence, true class confidence, entropy. Attack classifier: logistic regression, evaluated on target member versus non member sets.

Latest full run metrics:

Attack Accuracy 0.550
ROC AUC 0.575
TPR @ 1% FPR 0.053
TPR @ 5% FPR 0.125

Takeaway

In this configuration, the attack signal is present but moderate. This is expected for small scale fine tuning and limited sample budgets. The result is still useful because it demonstrates the complete MIA pipeline, not just synthetic score fitting.

Experiment 2: Prompt injection

I benchmarked prompt injection on a real instruction model using HuggingFace generation. Model Qwen/Qwen2.5-0.5B-Instruct. Deterministic generation with temperature=0. Attack families: goal hijacking, role override, prompt leaking, instruction escape. Defenses: none, system prompt hardening, delimiter wrapping, output filtering. Scoring uses indicator based success after extracting assistant output and checking refusal patterns.

Defense level success rates from the latest run:

Defense Observed Attack Success Rate
none0.00
system_prompt0.25
delimiters0.00
output_filter0.00

Family level results showed one consistent weak point: prompt leak style requests still achieved partial success in this setup.

Takeaway

Prompt defenses should be treated as layered controls, not a single fix. Even when most attacks are blocked in a small benchmark, edge cases remain and evaluation quality depends heavily on scoring design and test coverage.

Reproducibility and engineering details

CLI control: model, dataset, sample sizes, epochs, and seed are configurable. Artifact export: metrics JSON, plots, and per row prompt injection CSV are written to outputs/. Run scripts: quick and full workflows are available via run_experiments.sh and direct Python commands. Framework stack: PyTorch, HuggingFace Transformers, HuggingFace Datasets, and sklearn.

Limitations

Current runs are small scale CPU benchmarks for reproducibility and iteration speed. Prompt injection scoring uses rule based heuristics, not human adjudication. There is no tool use agent setup yet; attacks target direct model prompting only.

Interactive mini demo: prompt injection simulator

This browser demo is a toy simulation, not an actual model. It helps visualize how a payload can bypass weak policy handling.
